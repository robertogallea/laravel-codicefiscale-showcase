# Depend on laravel-codicefiscale via a local path repository on its `dev` branch

laravel-codicefiscale v3 is a ground-up rewrite with no tagged Packagist release yet; the only place it exists is a working checkout at `/home/roberto/code/packages/laravel-codicefiscale`. We require it via a composer path repository pinned to the `dev` branch (`dev-dev`), the same mechanism a sibling prototype app already used, rather than waiting for a release.

That shared checkout was already sitting on a different branch (`feature/108-localized-validation-messages`) for the sibling app's own work, and a `path` repository's version is inferred from whatever branch is physically checked out on disk — switching it would have silently broken that other app. Instead we added a second `git worktree` for the same repository, checked out at `dev`, at `/home/roberto/code/packages/laravel-codicefiscale-dev`, and pointed this app's path repository at the worktree rather than the original clone. Both apps now read the same underlying `.git`, each from its own independently-checked-out branch.

**Consequences**: `composer.lock` pins whatever commit `dev` is at when installed, not a stable version — re-running `composer update` picks up whatever's on that branch at the time, so the build isn't reproducible from the lock file alone the way a tagged dependency would be. Anyone cloning this repo needs that same worktree present at `/home/roberto/code/packages/laravel-codicefiscale-dev` (or an equivalent `dev`-branch checkout) to `composer install` it — a plain clone of the upstream repo on its default branch is not sufficient.
