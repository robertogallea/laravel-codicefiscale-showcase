# Depend on laravel-codicefiscale via the real remote `dev` branch, not a pinned local worktree

Supersedes ADR-0002. The package is registered on Packagist, which tracks every branch of its GitHub repo automatically — `robertogallea/laravel-codicefiscale: dev-dev` resolves directly against the real `dev` branch with no path repository or explicit VCS repository entry needed. We removed the path repository pointing at the local worktree (`/home/roberto/code/packages/laravel-codicefiscale-dev`) and re-ran `composer update`, which now downloads the package from GitHub via Packagist instead of symlinking the local checkout.

This is a deliberate reversal of ADR-0002, made after that ADR's own documented risk actually happened once (see its "Incident" note): the local path repository's whole point was pinning to a commit *we* choose to advance, but it turned out to be easy to accidentally lose (an uncommitted `composer.json` change) with no visible symptom until something downstream broke. Tracking the real branch directly removes that failure mode by making "what commit are we on" Composer's own concern again, at the cost of losing the ability to hold back a specific commit.

**Consequences**: `composer.lock` now pins whatever the real `dev` branch's HEAD was at `composer update` time, sourced from `https://github.com/robertogallea/laravel-codicefiscale.git` — still not reproducible from the lock file alone the way a tagged release would be (ADR-0002's core caveat still applies), but a fresh clone no longer needs any local package checkout to `composer install`; it only needs network access to GitHub/Packagist. The local worktree at `/home/roberto/code/packages/laravel-codicefiscale-dev` is no longer read by this app - left in place (harmless) unless removed separately.
